# Бот в MAX как второй канал доставки и мониторинга

## Why

Часть сотрудников и руководителей ведёт переписку с клиентами и общается внутри компании в мессенджере MAX, а не в Telegram. Сейчас продукт умеет собирать и анализировать сообщения только Telegram-чатов и доставлять саммари/алерты только через Telegram-бота — получатели и чаты, живущие в MAX, вообще не видны системе. `MAX_BOT_TOKEN` уже выдан платформой, поэтому можно подключить MAX как полноценный второй канал, не затрагивая работающий Telegram-контур.

## What Changes

- Добавляется `server/integrations/max-client.ts` — тонкий клиент MAX Bot API (аналог `telegram-client.ts`): получение обновлений (long polling, вебхук — опционально), отправка/редактирование сообщений, ответ на нажатие кнопки, подписка на вебхук.
- Приём событий MAX зеркалирует Telegram-конвейер: webhook/polling → сырая очередь апдейтов → воркер `intake` → сообщения поддержки, команды бота (`/start <код>`, аналог `bot_started` с `payload`), подключение группы по коду, нажатия кнопок.
- У чата появляется признак канала (`telegram` или `max`) — фиксируется один раз при первом появлении чата, в зависимости от того, какой бот его увидел. Чат живёт только в одном канале; дирекции, права, правила, анализ, инциденты — без изменений, канал не влияет на бизнес-логику анализа.
- Получатель (`recipients`) может быть привязан одновременно к Telegram и к MAX (два независимых идентификатора и статуса привязки на одной записи), а не только к одному каналу.
- Доставка саммари, алертов, обновлений инцидентов и дайджеста «Что сейчас происходит» уходит через ту поверхность, из которой пришёл контент: алерт/обновление инцидента чата MAX — в MAX, периодический отчёт собирается и отправляется отдельно по каждому каналу, на котором у получателя есть подключённые чаты (если у получателя есть чаты и в Telegram, и в MAX — он получает два отдельных сообщения за период, а не одно смешанное).
- Меню бота, тестовое уведомление и технические уведомления отправляются по каждому каналу, к которому получатель активно привязан, — независимо друг от друга.
- Очередь доставки (`delivery_jobs`/`delivery_attempts`) получает признак канала, чтобы при обработке задания выбирать нужный клиент (Telegram или MAX) и идентификатор получателя для него.
- Rich-HTML-отправка (таблицы, сворачиваемые блоки — Bot API 10.1) остаётся только для Telegram: у MAX такой возможности нет, туда саммари и дайджест уходят обычным текстом (как уже работающий fallback-путь при отказе rich-отправки в Telegram).
- Админка: в карточке и списке получателей видны оба канала привязки (идентификатор, статус, своя ссылка/код привязки, кнопки «отправить меню»/«тестовое уведомление» на каждый канал отдельно).
- Переменные окружения: `MAX_BOT_TOKEN`, `MAX_MODE` (`polling` по умолчанию в prod — как сейчас для Telegram, домен деплоя снаружи недостижим; `off` по умолчанию в dev), `MAX_WEBHOOK_SECRET` — по аналогии с `TELEGRAM_*`.

Переделки существующего поведения не планируется — Telegram-контур работает без изменений, MAX подключается параллельно.

## Capabilities

### New Capabilities
- `max-ingestion`: приём событий MAX Bot API (long polling/вебхук), подключение MAX-групп к дирекциям, идемпотентное хранение сообщений и редакций, пробелы сбора — зеркало `telegram-ingestion` для второй поверхности.

### Modified Capabilities
- `recipient-binding`: привязка получателя становится per-channel — получатель может быть одновременно привязан к Telegram и к MAX, код/ссылка привязки выдаются на конкретный канал, конфликт и слияние проверяются в рамках канала.
- `directorates`: подключение чата руководителем по одноразовому коду работает через бота любого канала (Telegram или MAX); канал чата фиксируется тем ботом, который получил событие подключения.
- `notification-delivery`: доставка выбирает канал по источнику контента (чат/инцидент — канал чата; периодический отчёт — отдельно по каждому каналу, где у получателя есть подписки), ретраи/rate-limit/классификация ошибок применяются к API того канала, через который идёт отправка.
- `periodic-summaries`: периодический отчёт получателя строится и отправляется отдельно на каждый канал, где у него есть подключённые чаты за период; rich-формат остаётся только у Telegram, в MAX — обычный текст.
- `on-demand-digest`: дайджест «Что сейчас происходит» по нажатию в меню отражает чаты того канала, в котором нажата кнопка.
- `subscriptions`: настройка категорий и минимальной серьёзности алертов из меню бота доступна одинаково из Telegram и из MAX.
- `admin-console`: список и карточка получателя показывают привязку, статус и действия по каждому каналу отдельно, а не только по Telegram.
- `admin-auth`: публичный webhook-эндпоинт MAX добавляется в список исключений из требования сессии наравне с Telegram.
- `operations-monitoring`: `/api/ready` и метрики задержки приёма учитывают оба канала (бот MAX доступен/недоступен — отдельно от Telegram).
- `message-analysis`: запрет передавать в AI идентификаторы получателей расширяется с Telegram ID на идентификаторы любого канала.

## Impact

- **Схема БД** (`server/migrations.ts`): `chats.channel`, параллельные `max_*`-колонки у `recipients` (аналог `telegram_*`), `max_updates` (аналог `telegram_updates`), `channel` у `delivery_jobs`/`delivery_attempts`.
- **Интеграции**: новый `server/integrations/max-client.ts`.
- **Сервисы/репозитории**: `recipient-repository`/`recipient-service`, `chat-repository`, `ingestion-service`/`intake-service` (параметризация по каналу или отдельный MAX-вариант), `delivery-service`, `bot-command-service`, `callback-router`, `on-demand-service`, `report-service`/`digest-service`/`summary-scheduler-service` (разбивка отчёта по каналу).
- **Роуты**: `POST /api/max/webhook` (аналог `POST /api/telegram/webhook`).
- **Воркеры**: `polling`/`intake`/`delivery`/`monitor` начинают работать с двумя клиентами и двумя очередями приёма.
- **Фронтенд**: `src/routes/users.tsx`, `src/routes/user-details.tsx`, `src/lib/api.ts`, `src/hooks/use-recipients.ts` — отображение и управление привязкой по каждому каналу.
- **Контракты** (`shared/schemas.ts`): `RecipientSchema` получает поля MAX-канала, `MaxUpdateSchema` (аналог `TelegramUpdateSchema`), `BindingCodeSchema`/выдача кода параметризуются каналом.
- **Конфиг** (`server/config.ts`): `MAX_BOT_TOKEN`, `MAX_MODE`, `MAX_WEBHOOK_SECRET`.
- **Внешняя зависимость**: MAX Bot API (`https://platform-api2.max.ru`) — новый внешний сервис, доступность которого не контролируется проектом.
