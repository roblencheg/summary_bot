## MODIFIED Requirements

### Requirement: Health и readiness
Система SHALL предоставлять `/api/health` (процесс жив) и `/api/ready` (БД отвечает, фоновые воркеры активны, доступны настроенные боты — Telegram и/или MAX) без авторизации и без раскрытия внутренних данных. Недоступность одного настроенного бота MUST отражаться по его имени, не блокируя оценку готовности другого.

#### Scenario: Воркер завис
- **WHEN** воркер доставки не обновлял heartbeat больше 60 секунд
- **THEN** `/api/ready` отвечает 503 с именем неготового компонента

#### Scenario: MAX недоступен, Telegram работает
- **WHEN** настроены оба бота, а MAX Bot API не отвечает
- **THEN** `/api/ready` отвечает 503 с именем компонента «max», при этом Telegram-доставка продолжается без деградации

### Requirement: Метрики
Система SHALL показывать задержку поступления из каждого настроенного канала (Telegram, MAX) отдельно, задержку анализа и доставки, размер очередей, ошибки, количество сообщений, инцидентов и повторов, расход токенов AI и долю ложных сигналов, вычисляя их из данных БД.

#### Scenario: Расход AI
- **WHEN** администратор открывает обзор за сутки
- **THEN** видно суммарное число входных и выходных токенов AI и число вызовов

#### Scenario: Задержка по каналам раздельно
- **WHEN** в Telegram задержка поступления 2 секунды, а в MAX — 8 секунд
- **THEN** обзор показывает оба значения отдельно, не усредняя их в одну метрику

### Requirement: Защита секретов
Система MUST NOT записывать токены ботов (Telegram, MAX), ключи API, пароли и коды привязки в открытом виде в код, логи, интерфейс и аудит.

#### Scenario: Ошибка запроса к боту
- **WHEN** запрос к Bot API Telegram или MAX падает с ошибкой
- **THEN** в лог пишется канал, метод и код ошибки без URL и без значения токена
