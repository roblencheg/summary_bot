## MODIFIED Requirements

### Requirement: Состав отчёта
Система SHALL формировать одно персональное сообщение, которое начинается с вывода, а подробности даёт ниже. Порядок блоков:
1. Заголовок с периодом, часовым поясом и статусом полноты данных.
2. Блок «Обстановка», вычисляемый кодом без AI:
   - общий цвет (🔴 тревожно, 🟡 есть вопросы, 🟢 спокойно) — худший из цветов чатов;
   - строка итоговых чисел по всем чатам получателя: сообщения, обращения, возможно без ответа, активные инциденты по уровням;
   - «светофор по чатам» — по одной строке на чат с цветом и причиной цвета, отсортированный от худшего к лучшему.
3. Блок «Требует решения» — сквозной список по всем чатам получателя: активные инциденты и обращения «возможно, без ответа». В каждой строке: уровень, кто, где (чат), что (суть) и статус со ссылкой. Сортировка — по серьёзности, затем по времени; если пунктов нет, блок сообщает, что требующих решения вопросов нет.
4. Краткая картина от AI.
5. Разделы по каждому разрешённому чату. Заголовок раздела содержит цвет чата и итоговую фразу AI об обстановке (если она есть и подтверждена основаниями).
6. Общие повторяющиеся темы только среди чатов, разрешённых этому получателю.

Раздел чата SHALL содержать:
- число сообщений и уникальных авторов;
- число обращений, повторных обращений и сигналов риска;
- темы с количеством и долей среди классифицированных обращений, включая категорию «прочее/не определено»;
- кто с чем обращался: имя, суть, повторы, наблюдаемый статус значком и ссылка;
- тон с распределением и причинами;
- всплески;
- все активные инциденты и затянувшиеся проблемы;
- признаки ответа поддержки и возможные обращения без ответа.

Цвет чата SHALL определяться детерминированно:
- 🔴 — есть активный инцидент уровня «Высокий» или «Критический» либо всплеск;
- 🟡 — есть инцидент уровня «Требует внимания», обращения «возможно, без ответа» или негативный тон не менее чем у трети обращений с тоном;
- 🟢 — иначе;
- ⚪ — сообщений в периоде не было.

#### Scenario: Сообщения и обращения различаются
- **WHEN** в чате 12 сообщений составляют 4 обращения
- **THEN** отчёт показывает отдельно «сообщений: 12» и «обращений: 4»

#### Scenario: Числа сверены с БД
- **WHEN** отчёт сформирован
- **THEN** количество сообщений, авторов, обращений и всплесков совпадает с SQL-подсчётом по БД за тот же полуоткрытый интервал

#### Scenario: Общие темы между чатами
- **WHEN** получателю доступны чаты A и B, а тема «оплата» повторяется в A и C
- **THEN** в общих темах отчёта не упоминается чат C

#### Scenario: Обстановка с первого экрана
- **WHEN** в чате A есть активный инцидент уровня «Высокий», в чате B — два обращения «возможно, без ответа», в чате C всё спокойно
- **THEN** первым блоком после заголовка идёт «Обстановка: 🔴 тревожно», а светофор по чатам перечисляет A (🔴, с причиной), B (🟡, с причиной), C (🟢) в этом порядке

#### Scenario: Требует решения — кто, где, что
- **WHEN** в чате «Доставка СПб» у демо-участника 01 обращение без ответа поддержки
- **THEN** блок «Требует решения» содержит строку с именем «Демо-участник 01», чатом «Доставка СПб», сутью обращения, статусом «⏳ возможно, без ответа» и ссылкой

#### Scenario: AI недоступен
- **WHEN** дайджест построен без AI
- **THEN** блоки «Обстановка» и «Требует решения» всё равно присутствуют, потому что вычисляются по данным БД

### Requirement: Выборка обращений и пустые периоды
Система SHALL показывать в Telegram до 20 наиболее значимых обращений активного чата с пометкой, что это выборка; хранить полный список в веб-интерфейсе; показывать «сообщений не было» для пустого периода и «данные неполные» с интервалом при пробеле сбора.

#### Scenario: Активный чат
- **WHEN** в чате 37 обращений
- **THEN** в Telegram показаны 20 с пометкой «выборка: 20 из 37, полный список — в веб-интерфейсе»

#### Scenario: Нет сообщений против сбоя
- **WHEN** в чате A сообщений не было, а в чате B был пробел сбора 23:10–23:50
- **THEN** у A указано «сообщений не было», у B — «данные неполные: 23:10–23:50»
