## ADDED Requirements

### Requirement: Создание получателя
Система SHALL позволять администратору создать получателя с именем и необязательным Telegram ID и MUST показывать статус «пользователь не активировал бота» до первой успешной привязки в личном диалоге.

#### Scenario: Новый получатель
- **WHEN** администратор создаёт получателя
- **THEN** он виден в разделе «Пользователи» со статусом «не активировал бота»

### Requirement: Привязка по одноразовому коду
Система SHALL выдавать для получателя одноразовый код со сроком действия 24 часа и ссылку `https://t.me/<bot>?start=<код>`, хранить только хэш кода и MUST привязывать Telegram ID только по действующему коду, полученному в личном диалоге.

#### Scenario: Успешная привязка
- **WHEN** пользователь открывает ссылку и бот получает `/start <код>` в личном диалоге
- **THEN** получателю присваивается Telegram ID отправителя, код гасится, статус становится «активен»

#### Scenario: Просроченный или использованный код
- **WHEN** код просрочен или уже использован
- **THEN** бот отвечает, что код недействителен, привязка не меняется

#### Scenario: Привязанный Telegram ID не совпадает
- **WHEN** у получателя задан Telegram ID, а код ввёл другой пользователь
- **THEN** привязка отклоняется и событие пишется в аудит

#### Scenario: Старт без кода
- **WHEN** незнакомый пользователь отправляет `/start` без кода
- **THEN** бот объясняет, что доступ выдаёт администратор, и не раскрывает никаких данных

### Requirement: Устойчивый идентификатор
Система SHALL идентифицировать получателя по числовому Telegram ID и MUST NOT использовать username как идентификатор доступа.

#### Scenario: Смена username
- **WHEN** получатель меняет username в Telegram
- **THEN** доставка и права продолжают работать

### Requirement: Команды бота для получателя
Система SHALL отвечать в личном диалоге на `/status` перечнем активных подписок получателя (саммари и алерты отдельно, только его чаты) и на `/help` — инструкцией, и MUST NOT выдавать данные чатов через команды или параметры.

#### Scenario: Статус подписок
- **WHEN** активный получатель отправляет `/status`
- **THEN** бот показывает его чаты для саммари, его чаты и категории для алертов

#### Scenario: Попытка запросить чужой чат
- **WHEN** пользователь отправляет команду с ID чата, не входящего в его подписки
- **THEN** бот не возвращает данных этого чата

#### Scenario: Команды в группе
- **WHEN** команду `/status` отправляют в групповом чате
- **THEN** бот ничего не отвечает в группе

### Requirement: Отключение получателя
Система SHALL позволять деактивировать получателя или сбросить привязку и MUST прекращать ему отправку всех ещё не отправленных уведомлений.

#### Scenario: Деактивация
- **WHEN** администратор деактивирует получателя с запланированным саммари
- **THEN** саммари ему не отправляется, задание помечается «отменено: получатель отключён»
