# Дизайн

## Одна раскладка — два рендера

Порядок чатов, цвета, итоги, «Требует решения» и общие темы вычисляются в `summary-render.ts` (`plan`, `totals`, `decisionRows`, `commonTopics`) и используются и текстовым рендером (`ReportService.render`), и rich-рендером (`renderRich`). Так запасной формат и rich не расходятся по содержанию.

## Лимиты

Лимиты Telegram: 32 768 символов текста, 500 блоков. `renderRichWithinLimits` оставляет запас (≤30 000 символов, ≤480 блоков) и последовательно уменьшает список обращений по чату. Блоки считаются по открывающим блочным тегам — приближение с запасом.

## Доставка

Rich отправляется только если ещё не отправлена ни одна часть (`partsSent = 0`), чтобы повтор после частичной текстовой отправки не дублировал отчёт. При успехе задание помечается отправленным всеми частями. `bad_request` означает, что Telegram не принимает этот HTML; повтор бессмысленен, поэтому `rich_html` очищается и задание продолжается текстом. Сетевые ошибки и 429 обрабатываются как раньше (повтор), гарантия «at-least-once» сохраняется.

## Почему не markdown

HTML даёт таблицы с флагами `bordered striped compact` и `<details>`; экранирование HTML уже есть в проекте.
