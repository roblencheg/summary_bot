# Summary Bot

Самостоятельно развёртываемый сервис мониторинга групповых чатов Telegram и MAX: анализ сообщений, алерты об инцидентах, дневные и ночные саммари, сводка по запросу, дирекции и роли доступа. Веб-интерфейс на русском языке.

**Стек:** Node.js 24, React, Fastify, SQLite (WAL), локальное файловое хранилище. Облачная платформа подрядчика и внешний S3 не требуются. AI подключается через внешний API.

## Быстрый запуск на сервере

Нужны Docker Engine с Docker Compose v2, исходящий HTTPS в Telegram/MAX и к AI-провайдеру.

```bash
git clone https://github.com/roblencheg/summary_bot.git
cd summary_bot
cp .env.example .env
chmod 600 .env
nano .env
docker compose up -d --build
docker compose logs --tail=100 -f
```

В `.env` обязательно задайте:

```dotenv
PUBLIC_BASE_URL=https://summary.example.com
ADMIN_INITIAL_LOGIN=admin
ADMIN_INITIAL_PASSWORD=YOUR_UNIQUE_LONG_PASSWORD
```

Замените адрес на свой origin **без пути**, а пароль — на свой (не менее 10 символов). Для первого локального запуска используйте `PUBLIC_BASE_URL=http://localhost:3000`. По умолчанию порт доступен только на `127.0.0.1:3000`. Если reverse proxy находится на другом сервере или нужен доступ по LAN, задайте `BIND_ADDRESS=0.0.0.0` и ограничьте доступ сетевым экраном. Укажите в `PUBLIC_BASE_URL` фактический адрес, который открываете в браузере.

На Unraid: разместите checkout, например, в `/mnt/user/appdata/summary_bot`, настройте `.env` и выполните те же команды Compose. Данные находятся в именованном Docker volume `summary_bot_summary-data` (имя зависит от каталога/Compose project name); найдите фактическое имя через `docker volume ls`.

## Боты и AI

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота из BotFather |
| `TELEGRAM_MODE` | `off`, `polling` или `webhook`; пример выключен |
| `MAX_BOT_TOKEN` | Токен MAX-бота |
| `MAX_MODE` | `off`, `polling` или `webhook`; пример выключен |
| `TELEGRAM_WEBHOOK_SECRET` / `MAX_WEBHOOK_SECRET` | Секрет webhook; нужен при режиме `webhook` |
| `OPENAI_BASE_URL` | Базовый URL AI API, например `https://api.openai.com/v1` |
| `OPENAI_API_KEY` | Ключ AI-провайдера |
| `OPENAI_MODEL` | Начальная модель; затем меняется в системных настройках |
| `DEFAULT_TIMEZONE` | Начальный часовой пояс, например `Asia/Novosibirsk`; по умолчанию `UTC` |
| `PUBLIC_BASE_URL` | Origin интерфейса и webhook, для CORS и проверки Origin |
| `HTTP_PORT` / `BIND_ADDRESS` | Публикуемый порт / адрес Docker |
| `ADMIN_INITIAL_LOGIN` / `ADMIN_INITIAL_PASSWORD` | Первый суперадминистратор |
| `EXTRA_CA_CERTS` | Путь на хосте к дополнительному доверенному PEM CA bundle |

Для обычного сервера используйте `polling`: не требуется открывать webhook в интернет. Один токен должен обслуживать **один процесс** polling; отключите прежний экземпляр бота. Для включения заполните токен, замените `off` на `polling` и выполните `docker compose up -d`.

AI-провайдер должен поддерживать **Responses API (`/responses`) и strict JSON Schema**. Совместимости только с Chat Completions недостаточно. В отсутствие ключа интерфейс работает, но анализ и AI-сводки недоступны. Содержимое чатов передаётся указанному AI-провайдеру.

Если MAX возвращает ошибку доверия сертификату, получите проверенный CA bundle из доверенного источника и задайте `EXTRA_CA_CERTS=/absolute/path/to/ca-bundle.pem`. По умолчанию используется системный bundle хоста. Не отключайте проверку TLS. Исходный PEM в `server/certs/` оставлен как справочный ресурс и автоматически не подключается.

## Суперадминистраторы и первые настройки

Первый суперадминистратор создаётся из `ADMIN_INITIAL_*` **только в пустой БД**. Изменение этих переменных не сбрасывает пароль существующей учётной записи.

1. Войдите под первым администратором.
2. В «Настройки → Администраторы» создайте остальных суперадминов с собственными логинами и паролями.
3. Создайте свои дирекции и руководителей в «Дирекции».
4. Добавьте ботов в группы, выдайте необходимые права и подключите чаты через код дирекции. Для Telegram отключите Privacy Mode через BotFather, если бот должен читать обычные сообщения.
5. Настройте получателей, подписки, расписания, часовой пояс и модель AI.

Приложение стартует без фиктивных ФИО, чатов и дирекций. Историческая миграция создаёт «Основное подразделение» только для уже существующих непривязанных данных. Необязательные материалы обучающего ролика в `tutorial-video/` содержат синтетические данные с метками «Демо-участник»; они не загружаются при запуске и не попадают в Docker-образ. Демо-наполнение разрешено только с `ALLOW_DEMO_SEED=true` вне production.

## Reverse proxy (Zoraxy, Nginx и другие)

Направьте HTTPS-домен на `http://SERVER_IP:3000`, передавайте `Host` и `X-Forwarded-Proto`. `PUBLIC_BASE_URL` должен совпадать с origin в адресной строке. При HTTPS cookie автоматически получает `Secure`; локальный HTTP поддерживается. Развёртывание предполагает корень домена, не подпуть.

В режиме webhook нужен доступный извне HTTPS. Polling требует только исходящих запросов. Не используйте несколько реплик: SQLite, планировщик и polling рассчитаны на один процесс.

## Данные, копии и обновление

- `/app/data/summary.sqlite` — БД; рядом служебные WAL/SHM-файлы.
- `/app/data/storage/backups/` — ежедневные экспорты таблиц; срок хранения задаётся в UI.
- `/app/data/storage/guide/intro-video.mp4` — необязательный обучающий ролик.
- Все эти файлы сохраняются в volume `summary-data` между пересборками и перезапусками.

Ежедневный экспорт приложения сохраняет таблицы, но не является копией всего volume. Чтобы получить согласованный полный бэкап, остановите сервис, скопируйте volume средствами Docker/Unraid, затем запустите сервис. Храните дополнительную копию на другом носителе. При восстановлении полного volume сохраняйте UID/GID пользователя `node` (1000:1000). `docker compose down -v` удаляет данные.

```bash
# Обновление: сначала сохраните резервную копию volume.
git pull --ff-only
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:3000/api/health
curl -fsS http://127.0.0.1:3000/api/ready
```

Экспорт отдельных таблиц можно восстановить штатным `scripts/restore.ts` (см. код скрипта; дата в формате `YYYY-MM-DD`, затем `--confirm`); запускайте восстановление отдельно от основного процесса и только в подготовленную пустую БД.

## Разработка без Docker

Node.js 24 и pnpm 9.15:

```bash
pnpm install --frozen-lockfile
# .env Node читает явно; никакие секреты не встраиваются во фронтенд.
node --env-file=.env --import tsx server/index.ts
# В другом терминале:
pnpm dev:web
```

Бэкенд разработки работает на 3001, фронтенд — на 3000 с проксированием `/api`. Для production без Docker сначала `pnpm build`, затем:

```bash
NODE_ENV=production DATA_DIR=./data node --env-file=.env --import tsx server/index.ts
```

Проверки: `pnpm typecheck` и `pnpm build`. Для локального запуска бота задайте режим явно; без него при development приём выключен.

## Архитектура

`src/` — интерфейс, `shared/` — типы и Zod-контракты, `server/routes/` → `services/` → `repositories/` — API и бизнес-логика. `server/platform.ts` содержит адаптеры SQLite и файлового хранилища, `server/migrations.ts` автоматически обновляет схему. `openspec/` содержит исторические требования исходного проекта.
